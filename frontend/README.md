# Frontend MVP

React + Vite + Redux Toolkit + Redux Saga, структура Feature-Sliced Design, минимальный Prettier. Node.js 22.12+ или 24 LTS.

## Запуск

Из корня репозитория:

```bash
npm --prefix frontend install
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-api.txt
npm run dev
```

`npm run dev` запускает FastAPI на `127.0.0.1:8000`, ждёт `/api/health` и запускает Vite на `127.0.0.1:5173`. Оба процесса останавливаются по Ctrl+C. Если зависимости не установлены, команда выводит инструкцию. Если порт занят, новый сервер завершится с ошибкой, а не откроется незаметно на другом порту. Для явного выбора порта: `FRONTEND_PORT=5174 npm run dev`.

Поиск по названию доступен с первого экрана без фото: RAG использует подготовленную `chroma_db/`, а при недоступности RAG сервис ищет по сохранённому `data/ozon_categories.json` с явной пометкой источника. Для поиска по каталогу ключи Ozon, Yandex и VseGPT не нужны.

Для распознавания фото создайте `backend/.env` по `backend/.env.example` и задайте `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`. При необходимости модель переопределяется через `YANDEX_MODEL`. Для автоматического подбора категории после фото нужны полный `backend/requirements.txt` и построенная база RAG (`npm run rag:build` из корня). `VSEGPT_API_KEY` нужен только для дополнительного уточнения результата ИИ; без него RAG предлагает найденную категорию на подтверждение. Модель VseGPT переопределяется через `VSEGPT_MODEL`. Для получения актуального дерева, атрибутов и справочников нужны `OZON_CLIENT_ID` и `OZON_API_KEY`. После изменения ключей перезапустите backend.

Если распознавание недоступно, форма поиска по названию остаётся доступной. ID категории выбираются вместе с результатом поиска; вводить их вручную не требуется.

Отдельные процессы и проверки:

```bash
npm run dev:frontend
npm run dev:backend
npm run build
npm --prefix frontend run preview
npm --prefix frontend test
npm --prefix frontend run format
npm --prefix frontend run format:check
.venv/bin/python -m unittest discover -s backend/tests -v
```

Сборка записывается в `frontend/dist`. Vite dev и preview проксируют `/api` на `BACKEND_URL` (по умолчанию `http://127.0.0.1:8000`); backend должен быть запущен отдельно для preview. При размещении `dist` на обычном веб-сервере настройте reverse proxy `/api` или `VITE_API_BASE_URL` перед сборкой. Ключи не должны попадать в `VITE_*`.

Если браузер показывает старые подписи или другую разметку, проверьте адрес, порт и каталог ранее запущенного Vite. Завершите старый процесс в его терминале и перезапустите из текущего проекта.

## Структура

```text
src/
  app/                    # App, Redux store, Saga middleware
  pages/create-product/   # Компоновка одного экрана MVP
  features/product-setup/ # Slice, саги, форма атрибутов
  entities/product/       # Работа с деревом и метаданными
  shared/                 # HTTP-клиент, общие стили
```

Саги выполняют распознавание → RAG, поиск категорий, загрузку атрибутов и пагинацию справочников, сохранение/восстановление черновика. Redux хранит сериализуемые данные; фото, превью и drag-and-drop остаются в локальном состоянии страницы.

Фото: JPG, PNG, WebP, максимум 10 МБ. Поля формы строятся по API, включая необязательные поля, группы, Boolean, Integer/Decimal, текст, дату, справочники и множественные значения. Сложные атрибуты отображаются как отдельные поля с ID группы; полноценный редактор повторяемых связанных наборов и экспорт в формат публикации Ozon не реализованы.

Черновик сохраняется под ключом `ozon-assistant-draft-v1` в localStorage; незаполненные поля допускаются. Фото не сохраняется. Для восстановления нажмите «Открыть черновик» на первом шаге. Публикация на маркетплейсе отсутствует.

Сценарий фото использует `/api/recognize-product` (название + категория + оба Ozon ID). Уже найденная backend-категория сохраняется без повторного запроса. Если RAG недоступен, название и фото остаются в интерфейсе, отображается конкретная причина и варианты ручного выбора. `/api/health` показывает версию API и признаки настройки без значений ключей.

В форме по умолчанию показаны обязательные поля и основные свойства для категории товара, сгруппированные по смыслу. PDF, rich-контент/JSON, видео и другие необязательные поля интеграций скрыты. Редкие дополнительные свойства находятся в свёрнутом блоке. Исходная схема API и сохранённые значения не урезаются. Политика приоритетов: `src/entities/product/model/attribute-layout.js`; она не задаёт статические значения и типы полей.
