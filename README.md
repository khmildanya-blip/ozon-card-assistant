# Автоматическое заполнение карточек товара на Ozon
## Цель проекта

Сократить время заполнения карточек товаров: объединить подбор категории, генерацию описания, работу с фотографиями и публикацию через Ozon Seller API в одном веб-приложении.

## Планируемые возможности

- Подключение магазина через Ozon Seller API.
- Создание, редактирование и сохранение карточек с обязательными характеристиками.
- Генерация описаний и рекламных слоганов через API нейросети.
- Загрузка фотографий с телефона и съёмка через камеру в приложении.
- Ручное редактирование слоганов и размещение их на титульном фото по шаблону.
- Отправка заполненных карточек на Ozon.
- Адаптивный интерфейс и установка приложения как PWA.

**Примечание:** это целевые возможности проекта, а не перечень полностью реализованных функций.

## Этапы разработки проекта

### 1. Первое демо — базовый прототип

**Цель:** продемонстрировать работоспособность ключевых технологий.

- Реализация RAG-системы для поиска и получения информации.
- Распознавание и определение объектов по фотографии.
- Демонстрация базового сценария работы системы.

### 2. Второе демо — функциональный прототип

**Цель:** представить полноценный пользовательский сценарий с удобным интерфейсом и сохранением данных.

- Разработка формы регистрации и авторизации пользователей.
- Создание полноценного пользовательского интерфейса.
- Подключение базы данных.
- Реализация сохранения и просмотра ранее созданных карточек.
- Интеграция разработанных компонентов в единую систему.

### 3. Защита проекта — итоговая версия

**Цель:** продемонстрировать завершённую систему с автоматизированной обработкой информации.

- Реализация парсинга данных из внешних источников (перспективно).
- Доработка и интеграция системы распознавания.
- Объединение всех модулей в единый продукт.
- Демонстрация полного цикла работы системы.

## Текущее состояние

Реализован React MVP на Vite с Redux Toolkit, Redux Saga и FSD: загрузка фотографии, распознавание через Yandex, подбор категории через RAG (Chroma + VseGPT), подтверждение или ручной выбор категории, получение реальных атрибутов Ozon, ручная форма и локальный черновик.

Интерфейс светлый, с синими акцентами, адаптируется под мобильную ширину. Регистрации, страницы готовой карточки и публикации на Ozon в первом демо нет. ТЗ: `docs/frontend_spec_first_demo_draft.md`. Архитектурные договорённости для Codex: `AGENTS.md`.

## Быстрый локальный запуск

Нужен Node.js 22.12+ или 24 LTS и Python 3.12+. Из корня:

```bash
npm --prefix frontend install
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-api.txt
npm run dev
```

Одна команда `npm run dev` запускает backend на `127.0.0.1:8000` и актуальный React frontend на `127.0.0.1:5173`. Vite стартует после успешной проверки `/api/health`. Ctrl+C останавливает оба процесса. Для другого frontend-порта используйте `FRONTEND_PORT=5174 npm run dev`.

Ручной поиск категории по названию работает без фотографии, API-ключей и базы векторов: если RAG не подготовлен, используется сохранённый каталог Ozon с пометкой источника. Вводить идентификаторы вручную не нужно. Для семантического поиска и подбора ИИ подготовьте полный RAG, как описано ниже.

Распознавание фото требует `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в `backend/.env` (файл `.env.example` автоматически не загружается); при отсутствии настроек интерфейс показывает конкретную ошибку и позволяет искать по названию. Для атрибутов и справочников нужны ключи Ozon. После изменения настроек перезапустите backend. Проверка настроек без вывода ключей: http://127.0.0.1:8000/api/health.

```bash
npm run dev:frontend                    # Только Vite
npm run dev:backend                     # Только FastAPI из .venv
npm run build                           # Production-сборка frontend
npm --prefix frontend run preview
npm --prefix frontend test
npm --prefix frontend run format
npm --prefix frontend run format:check
```

Результат сборки: `frontend/dist`. Vite dev и preview проксируют `/api` на backend. Для публикации статического `dist` нужен reverse proxy либо `VITE_API_BASE_URL` при сборке. Подробнее: [frontend/README.md](frontend/README.md).

Если на `5173` уже работает старый Vite, завершите его в прежнем терминале и запустите проект из текущего каталога. Порты фиксированы, поэтому занятый порт вызывает явную ошибку.

```text
frontend/                         # React + Vite, Redux Saga, FSD

  ozon_categories.py              # Получение дерева категорий Ozon
```

Локальные `.env`, `chroma_db/`, `local_translator/` и `uploads/` располагаются в корне репозитория и не включаются в Git.

## Технологии

Python, FastAPI, Uvicorn, LangChain, Chroma, Hugging Face Transformers, PyTorch, Pillow, Ozon Seller API и VseGPT API.

Для будущего интерфейса предусмотрены адаптивная вёрстка, браузерный режим и PWA. Целевые устройства — Android 11+ с Chrome и iOS 12+ с Safari; совместимость и ограничения PWA необходимо проверить при реализации. Облачное хранилище ещё не выбрано: например, Yandex Object Storage можно использовать для фотографий, а для карточек и пользователей потребуется отдельная база данных.

## Подготовка backend

Из корня репозитория, рекомендовано Python 3.12:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
cp backend/.env.example backend/.env
```

В `backend/.env` заполните `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `VSEGPT_API_KEY`, `OZON_CLIENT_ID`, `OZON_API_KEY`. Ключи не должны попадать в браузер или Git. Распознавание использует облачную модель Yandex; локальная модель перевода не нужна.

Для RAG нужна векторная база `chroma_db/` с коллекцией `ozon_categories` из `data/flat_docs.jsonl` и модель эмбеддингов `intfloat/multilingual-e5-base`. Для построения:

```bash
python scripts/build_db.py
```

Скрипт строит индекс 8 348 конечных типов из сохранённого официального дерева `data/ozon_categories.json`. Он загружает модель в `.cache/models`, исключает узлы-категории и пустые метаданные, записывает документы пакетами со стабильными ID. Существующая база не удаляется, повторный запуск готового индекса ничего не меняет; прерванное построение можно повторить. При изменении каталога укажите новый путь через `--db-dir` и задайте тот же путь в `RAG_DB_DIR` для backend.

Из корня также доступна команда `npm run rag:build`. Первичная загрузка модели и индексация могут занять несколько минут. Во время построения API сообщает `rag_index_building`, а не «поиск не реализован».

После фото frontend вызывает `POST /api/recognize-product`: backend распознаёт название, передаёт его в RAG и возвращает `category` с `description_category_id` и `type_id`. Frontend сохраняет найденную категорию и показывает подтверждение. При подтверждении эти два ID уходят на получение атрибутов. Уточнение через VseGPT опционально: при недоступности ключа/модели результат семантического поиска сохраняется с пояснением. Не запускайте скрипты обновления каталога без намерения перезаписать данные.

```bash
python -m uvicorn main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

OpenAPI: http://127.0.0.1:8000/docs. База и модели RAG загружаются отложенно; при недоступности RAG ручной поиск использует каталог. Для полного сценария нужны сеть, действующие ключи и подготовленная база.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка доступности без вызова внешних сервисов |
| POST | `/api/search-categories` | Поиск по названию: RAG + сохранённый каталог, без ввода ID |
| POST | `/api/recognize-product` | Фото → название → RAG → категория с двумя ID и кандидатами |
| POST | `/api/recognize-image` | Multipart `file`, JPG/PNG/WebP до 10 МБ → название и описание |
| POST | `/api/generate-description` | Название и особенности → категория через RAG |
| GET | `/api/categories` | Дерево категорий и типов из Ozon |
| POST | `/api/get-category-attributes` | Все атрибуты выбранной категории с метаданными |
| POST | `/api/attribute-values` | Справочник атрибута с пагинацией |
| POST | `/api/upload-image` | Отдельная загрузка файла (основной сценарий передаёт файл напрямую на распознавание) |

## Проверки и ограничения

```bash
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run format:check
python -m unittest discover -s backend/tests -v
```

Тесты проверяют цепочку распознавание → RAG, сохранение метаданных, пагинацию справочников, обработку ошибок и контракт API. Внешние сервисы в тестах заменены моками. Успешные тесты не подтверждают доступность Yandex, VseGPT и Ozon с конкретными ключами.

Черновики сохраняются локально в браузере без фото. Комплексные атрибуты отображаются отдельными полями; редактор повторяемых связанных наборов и экспорт для публикации в MVP не входят.


Дополнительные файлы из Downloads сверены: они побайтно совпадают с `data/ozon_categories.json` и `data/attributes_17028715_96250.json`. Второй файл — сохранённая схема только для «Дом и сад → Аксессуары для цветов → Горшок для цветов» (`17028715 / 96250`). Он используется в интеграционных тестах; для других типов не применяется и не подменяет живой ответ Ozon.
