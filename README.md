# Автоматическое заполнение карточек товара на Ozon
## Цель проекта

Сократить время заполнения карточек товаров: объединить подбор категории, генерацию описания, работу с фотографиями и публикацию через Ozon Seller API в одном веб-приложении.

## Планируемые возможности

- Подключение магазина через Ozon Seller API.
- Создание, редактирование и сохранение карточек с обязательными характеристиками.
- Генерация описаний и рекламных слоганов через API нейросети.
- Загрузка фотографий с телефона и съёмка через камеру в приложении.
- Ручное редактирование слоганов и размещение их на титульном фото по шаблону.
- Отправка заполненных карточек на Ozon.
- Адаптивный интерфейс и установка приложения как PWA.

Это целевые возможности проекта, а не перечень полностью реализованных функций.

## Текущее состояние

В репозитории находится прототип Python-бэкенда и скрипты для работы с каталогом Ozon:

- FastAPI-маршруты для генерации описания, загрузки и распознавания изображений.
- Поиск категорий через Chroma и модель `intfloat/multilingual-e5-base`.
- Выбор категории через DeepSeek, подключённый через VseGPT API.
- Распознавание изображений моделью `Salesforce/blip-image-captioning-large` и перевод через локальную модель Marian.
- Скрипты получения категорий и атрибутов Ozon, подготовки документов и построения векторной базы.
- Сохранённый каталог из 9 796 узлов и пример атрибутов категории.

Фронтенд, PWA, хранение карточек пользователей, генерация надписей на фотографиях и отправка готовых карточек на маркетплейс пока не реализованы. Приложение не развёрнуто на хостинге.

## Структура репозитория

```text
backend/
```

Локальные `.env`, `chroma_db/`, `local_translator/` и `uploads/` располагаются в корне репозитория и не включаются в Git.

## Технологии

Python, FastAPI, Uvicorn, LangChain, Chroma, Hugging Face Transformers, PyTorch, Pillow, Ozon Seller API и VseGPT API.

Для будущего интерфейса предусмотрены адаптивная вёрстка, браузерный режим и PWA. Целевые устройства — Android 11+ с Chrome и iOS 12+ с Safari; совместимость и ограничения PWA необходимо проверить при реализации. Облачное хранилище ещё не выбрано: например, Yandex Object Storage можно использовать для фотографий, а для карточек и пользователей потребуется отдельная база данных.

## Подготовка окружения

Команды выполняются из корня репозитория. Для облачного прототипа проверена установка на Python 3.12 с CPU-версией PyTorch.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install 'torch==2.14.1+cpu' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r backend/requirements.txt openai python-dotenv 'sentence-transformers==5.7.0' 'transformers==4.57.6'
python -m pip check
```

`openai`, `python-dotenv` и `sentence-transformers` указаны отдельно, поскольку код использует их, а текущий файл зависимостей не перечисляет их явно. При использовании локального окружения `.venv/` не добавляйте его в Git.

Для полного запуска также нужны:

1. Ключ `VSEGPT_API_KEY`, заданный в окружении или в локальном `.env` в корне проекта. Не добавляйте значения ключей в Git.
2. Доступ к `api.vsegpt.ru` и Hugging Face для загрузки моделей и их файлов.
3. Локальная модель перевода Marian с английского на русский в `local_translator/`. Конкретная модель в репозитории не указана.
4. Векторная база `chroma_db/`, построенная из `data/flat_docs.jsonl`.

После подготовки модели эмбеддингов база создаётся командой:

```bash
python scripts/build_db.py
```

Повторный запуск может добавить дубликаты в существующую коллекцию. Скрипты подготовки данных перезаписывают файлы каталога; запускайте их только при намеренном обновлении данных.

Скрипты обращения к Ozon содержат встроенные реквизиты доступа и выполняют запрос при запуске или импорте. До их использования необходимо заменить реквизиты безопасной конфигурацией и отозвать опубликованный ключ. В рамках обновления структуры их логика не менялась.

## Запуск API: текущее ограничение

Сейчас `backend/main.py` импортирует `get_chain` из `backend/rag.py`, но такой функции в модуле нет. Также ожидаемый маршрутом интерфейс `chain.invoke()` не соответствует текущей функции `find_ozon_category()`. До устранения этого несоответствия API не готов к запуску.

После исправления интерфейса и подготовки моделей и базы команда запуска из корня проекта:

```bash
python -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000
```

После успешного запуска схему API можно проверить запросом к `/openapi.json`, интерактивную документацию — через `/docs`.

| Метод | Маршрут | Назначение в прототипе |
| --- | --- | --- |
| POST | `/api/generate-description` | Генерация текста; интеграция с текущим RAG требует исправления |
| POST | `/api/upload-image` | Загрузка фотографии |
| POST | `/api/recognize-image` | Распознавание и перевод описания фотографии |

## Что проверено

- Синтаксис Python после изменения структуры.
- Совпадение результата преобразования дерева категорий со всеми 9 796 документами `flat_docs.jsonl`.
- Установка зависимостей и отсутствие конфликтов по `pip check` в облачной среде.
- Запись и поиск документов в Chroma с тестовыми векторами.

Полный запуск API, нейросетевой поиск, распознавание изображений и запросы к VseGPT не подтверждены. Автоматизированного набора тестов в репозитории пока нет.
