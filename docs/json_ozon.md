# Руководство по заполнению атрибутов для Ozon API

Данный документ описывает правила формирования массива `attributes` при отправке данных о товаре через API Ozon (например, метод `/v2/product/import`), основываясь на схеме атрибутов категории.

## Базовая структура

В итоговом JSON для отправки на Ozon атрибуты передаются в виде массива объектов внутри ключа `attributes`. Каждый объект атрибута имеет следующую базовую структуру:

```json
{
  "id": 123,           // ID атрибута из схемы
  "complex_id": 0,     // Обычно 0 (используется для сложных вложенных атрибутов)
  "values": [          // Массив значений (даже если значение одно)
    {
      "value": "Текст",                  // Текстовое/числовое представление
      "dictionary_value_id": 456         // Опционально: ID значения из словаря (если требуется)
    }
  ]
}
```

## Правила заполнения на основе схемы

При чтении схемы атрибутов (полученной от API Ozon), обращайте внимание на следующие ключевые параметры для каждого поля:

### 1. Обязательность поля (`is_required`)
*   **Если `"is_required": true`**: Вы **обязаны** передать это поле в итоговом JSON. Без него Ozon вернет ошибку.
*   *Частые обязательные поля:* Бренд (ID: 85, если нет - пишем "Нет бренда"), Тип (ID: 8229), Название модели (ID: 9048).

### 2. Тип данных (`type`)
Определяет, в каком формате передавать `value` внутри массива `values`:
*   **String** (строка): Текст в кавычках. Пример: `"value": "Аннотация"`.
*   **Integer** (целое число): Число в виде строки. Пример: `"value": "10"`.
*   **Decimal** (число с плавающей точкой): Число через точку, передается как строка. Пример: `"value": "2.5"`.
*   **Boolean** (логическое значение): Передается в виде строки. Пример: `"value": "true"` или `"value": "false"`.
*   **URL**: Прямая ссылка на медиа-файл.

### 3. Множественные значения (`is_collection`)
*   **Если `"is_collection": true`**: В массив `values` можно передать несколько объектов.
*   *Пример (Цвет товара):*
    ```json
    "values": [
      { "value": "Красный" },
      { "value": "Белый" }
    ]
    ```
*   **Если `"is_collection": false`**: В массиве `values` должен быть строго один объект.

### 4. Словарные значения (`dictionary_id`) — ВАЖНО!
*   **Если `"dictionary_id": 0`**: Значение можно вписывать свободно (пользователь вводит текст с клавиатуры).
*   **Если `"dictionary_id" > 0` (например, 1960)**: Значение **нельзя** вписать произвольно. 
    1. Бэкенд должен сделать запрос к `/v1/description-category/attribute/values`, передав этот `dictionary_id`.
    2. Из полученного списка нужно выбрать подходящее значение.
    3. В итоговом JSON желательно передавать `dictionary_value_id` (ID выбранного значения) и само `value`.

## Полный пример итогового JSON (Блок attributes)

Вот пример того, как должен выглядеть готовый блок `attributes` в запросе к Ozon:

```json
"attributes": [
  {
    "id": 85,
    "complex_id": 0,
    "values": [
      {
        "value": "Нет бренда"
      }
    ]
  },
  {
    "id": 8229,
    "complex_id": 0,
    "values": [
      {
        "dictionary_value_id": 123456, 
        "value": "Горшок для цветов" 
      }
    ]
  },
  {
    "id": 9048,
    "complex_id": 0,
    "values": [
      {
        "value": "Модель Basic-1"
      }
    ]
  },
  {
    "id": 23536,
    "complex_id": 0,
    "values": [
      {
        "value": "false"
      }
    ]
  },
  {
    "id": 10096,
    "complex_id": 0,
    "values": [
      {
        "value": "Красный"
      },
      {
        "value": "Белый"
      }
    ]
  }
]
```

## Алгоритм работы для вашего приложения
1. **Фронтенд** парсит схему атрибутов (ваш файл `attributes_...json`).
2. Для каждого атрибута с `"is_required": true` рисует поле со звездочкой (обязательное).
3. Для каждого атрибута с `"dictionary_id" > 0` делает выпадающий список (Select), запрашивая опции у бэкенда.
4. Для `"is_collection": true` позволяет выбрать/ввести несколько тегов или галочек.
5. При нажатии "Сохранить", фронтенд собирает данные в массив `attributes` строго по формату выше и отправляет на ваш бэкенд, а тот пересылает на Ozon.
